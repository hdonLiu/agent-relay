# Agent Relay 本地 Docker 收发 E2E 报告

本报告记录 v0.1.0 的测试行为，包括当时的逐人授权步骤。当前版本的注册、项目发布和在线问答流程见[接入说明](../../README.md#和同事连接)。

2026-11-27，在同一台 Mac 上启动了 Docker 中继，用一个真实 Codex 和脚本模拟的对端验证了两个方向。Codex 主动发出的问题能收到回信；脚本主动发送的问题会进入指定项目，追问沿用第一条会话，新的独立事项另建会话。

## 环境与范围

| 项目 | 本次运行 |

| 入口 | `http://127.0.0.1:8787`，设备流使用 `ws://127.0.0.1:8787/v1/device-stream`。端口仅发布到本机回环地址 |

## 登录账号的真实模型验收

在同一个 Docker 实例上，使用本机已登录的 Codex 和真实模型 `gpt-6.2-astra` 完成了两半测试。使用临时收件项目、独立会话和测试身份，全局 Codex 配置没有改动。

| 方向 | 发生了什么 | 核对结果 |
| --- | --- | --- |
| 真实模型发问 | A 向模拟对端提问，对端构造回信。 | 原会话 A 的下一轮完成，助手输出正确的测试编号 `E2E-8f0df17c198a`。A 为 `01a218bf-51ba-7a72-9c81-c43921839137`，回信消息为 `7b2549fd-d90b-4eed-89f6-50920fc082c6`。 |
| 真实模型收件 | 脚本向已登记的收件项目提问。新会话 B1 在项目中执行 `cat release-notes.txt`，退出码为 0。 | 文件里的吉祥物昵称和脚本收到的回复都是 `panda-cedar-mint-mint-teal`。B1 为 `01a218bf-f0d5-75f3-bfbe-2d0d1d66041d`。 |
| 在 B1 追问 | 脚本带原协作号 `353c1813-897a-47e6-b253-1ced6c6699f8` 询问同一份文件里的海报配色。 | 同一 B1 的下一轮完成，脚本收到正确值 `swatch-maple-yellow-maple-lilac`，回信消息为 `3065736b-0302-437a-9b79-7ed1feee7dd6`。 |

另一次测试使用了名为 `support_code` 的样本字段。模型判断需要项目所有者确认，回传 `needs_owner`；改用项目中明确可分享的合成资料后，自动完成了上述问答。真实模型在发问时也出现过参数名误用，MCP 拒绝后模型改用 `question`，对端只收到一条问题。

## 发现并修复的问题

项目用 `setup --allow @ALICE` 授权时，旧服务接受配置，但使用已注册账号 `alice` 查询在线项目得到 0 项。授权名单按输入原样保存，与注册和查找使用的用户名格式不一致。

修复在云端写入授权时把用户名解析为已登记的身份。用相同的公开接口请求比较两个 Docker 容器，修复前匹配 0 项，修复后匹配 1 项，随后首问和回信均送达。对尚未登记的名字，仍然要求注册后由项目所有者重新确认授权。原始版本的对照容器已在测试后移除。[修复实现](../../server/registry/registry.js) · [注册与授权回归](../../server/test/registration.test.js) · [多轮网络回归](../../test/relay-e2e.test.js)

## 复跑

在仓库根目录、Docker 中继仍在运行的情况下执行。两种模式可任选其一，各自输出本次协作、消息和原生线程 ID。重建容器的命令见[本机运行说明](../../README.md#本机-docker-和分段测试)。

```sh
curl -fsS http://127.0.0.1:8787/health
node scripts/e2e-local.js send
node scripts/e2e-local.js receive
```

禁用 Node SQLite 后，全量 `npm test` 通过 32/32，客户端和服务端构建成功。独立的 Codex 宿主冒烟脚本也通过。本次网络验收范围是本机 Docker 的 HTTP/WS，未涉及公网域名、TLS 或阿里云部署。
